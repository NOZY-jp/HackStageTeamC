# 仮データの検査（ChatGPT・Gemini などがデータを入れるときの手引き）

各プラットフォームの仮データ（`lib/<platform>/data/`）を足したり直したりしたら、次を流してください。CI（`npm test`）でも毎回流れます。

```bash
npm run data:check
```

失敗したら、表示された違反を直してから PR を出します。

## 何を検査するか

| 決まり                      | 内容                                                                                                                                                                 | 正本                               |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `forbidden-word`            | 「ゆい」「ゆっちゃん」と旧呼称の表記ゆれを作中に出さない                                                                                                             | #76                                |
| `real-name-outside-allowed` | 彼女の本名と代表的な読みは、段階8のぽちブロのコンテスト結果と、段階10の TalkUp の検索対象プロフィールだけに置く。ほかの人物の本名はどこにも置かない                  | #76（本名に届くのは段階8・10だけ） |
| `story-only-phrase`         | 物語の進み具合で届く文言（「住所を特定しました」「本名で検索したら」や典型的な言い換え）を、静的な過去のデータに置かない。物語の場面（`lib/story/scenario`）から流す | #119                               |
| `invalid-time`              | 実在する日付・時刻を ISO 8601 で書く。時刻つきはタイムゾーン必須（`+09:00` か `Z`）。登録日のような日付だけの値は `YYYY-MM-DD`                                       | ―                                  |
| `after-game-now`            | 静的なデータの日時は、ゲームの「いま」（`lib/data-check/rules.ts` の `GAME_NOW`）以前                                                                                | #119                               |
| `duplicate-id`              | 同一データセット内、および同じ入れ子の配列内で ID を重複させない                                                                                                     | ―                                  |
| 主要人物の名前              | Discord の表示名・ハンドルが名前の定数（`lib/discord-like/data/names.ts`）と同じ。Twixer に主要人物のハンドルがある。leaf に彼女の作者ページがある                   | #76（名前は1か所）                 |

検査は、登録済みデータセットのレコードから、日時・URL・色コードなどを除いた文字列を集めて調べます（`lib/data-check/corpus.ts`）。新しいデータのファイルを作ったら、`collectCorpus()` に1行足してください。

## この検査が見ないもの

- 会話相手による呼び方の使い分けは、Discord の人物表（`docs/discord/03-people.md`）と `lib/discord-like/naturalness.test.ts`、`lib/discord-like/data-people.test.ts` を確認する。
- 旧アカウントやマイリストの手がかりをどこに出すかは、#76 の順序と該当プラットフォームのテストで確認する。画像内の文字や JSX の直書きは収集しない。
- 会話の水増しや機械的な文体は、#154 の `lib/discord-like/naturalness.test.ts` と Discord の会話ガイドを確認する。
- 助言の検査は定義済みの語形が対象。意味だけが同じ言い換えや、会話の流れまでは判定しない。

## 失敗したとき

失敗の表示は「決まりの ID」「プラットフォーム/データ/ID」「何がいけないか」の順です。

```
story-only-phrase discord/dmMessages/dm-kai-0005 … 物語で届くはずの「住所を特定しました」が、静的なデータにある
```

- まず直す。名前は名前の定数を使い、物語で届く文言は物語の場面に移す
- すぐに直せず、直す Issue があるときだけ、`lib/data-check/known-issues.ts` に Issue 番号つきで足す。キーは、決まりの ID から違反内容まで含めて、失敗の表示をそのまま写す
- 直ったものが `known-issues.ts` に残っていても失敗する。#159 でカイの助言と結末を台本へ移すときは、その取り込みと同時に対応する2件を消す

## 決まりを足すとき

`lib/data-check/rules.ts` に関数を足して `RULES` に並べ、`rules.test.ts` に例を足します。正本（#76 など）に書いてあることだけを決まりにします。
