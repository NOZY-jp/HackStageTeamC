# SEO デモ手順書（Google で当たるかの確認）

手順3「ブログ名＋概要が結びつけば検索でヒット」と手順8「コンテスト名で本名がわかる」を、**実在の Google 検索**で成立させるための1枚です（#77・人の決定 2026-11-19）。ゲーム内に代替の検索画面は作りません。

- 対象URL: `https://hack-stage-team-c.vercel.app`
- 前提: `robots.txt` と `sitemap.xml` は 200、`sitemap.xml` にはブログ・コンテスト結果ページ・leaf（note）だけを載せる（Discord・Twixer は載せない）
- 実施者: 窓口（HackStage）。実装側はこの手順が成立する状態まで作る

## 1. Google での確認（手順3・8）

ブラウザのシークレットウィンドウで、上から順に検索します。

| #   | 検索語                                                 | 期待する結果                                                                           |
| --- | ------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 1   | `site:hack-stage-team-c.vercel.app`                    | サイトのページが1件以上出る。0件ならまだ未インデックス（§2 の登録をやり直す）          |
| 2   | `site:hack-stage-team-c.vercel.app でんでんの狩猟日記` | ブログのページ（`/pochiblo/denden0102`）が上位に出る＝手順3の成立                      |

コンテスト結果ページはサイト内のどこからもリンクしていません（`sitemap.xml` 経由でだけ届きます）。URL は sitemap から取ります。

## 2. Search Console への登録

1. Search Console を開き、プロパティを **URLプレフィックス** 方式で `https://hack-stage-team-c.vercel.app` として追加する（ドメイン方式ではない）。
2. 左メニューの「サイトマップ」に `sitemap.xml` を送信する（`https://hack-stage-team-c.vercel.app/sitemap.xml`）。
3. 「URL 検査」に対象URLを入れて「インデックス登録をリクエスト」する。最低限、次の3つを実施する。
   - `https://hack-stage-team-c.vercel.app/`
   - `https://hack-stage-team-c.vercel.app/pochiblo/denden0102`
   - コンテスト結果ページ（`sitemap.xml` に載っている URL）
4. 反映を待って、§1 の3つの検索をやり直す。

## 3. 所有確認（方式）

Google Search Console の所有確認は、**環境変数 `GOOGLE_SITE_VERIFICATION` にトークンを渡す方式を第一**とする（`app/layout.tsx` が `<meta name="google-site-verification">` を出す。未設定なら何も出さない）。トークンはリポジトリに書かず、Vercel の環境変数（Production / Preview）に設定する。設定後は再デプロイして、HTML にタグが出たことを確認してから Search Console で「確認」を押す。

代替: 環境変数を設定できない場合は、Search Console が配る HTML ファイルを `public/google<token>.html` に置く方式でも確認できる（ビルド不要で差し替えられるが、トークン入りのファイルがリポジトリに残るため第一手段は環境変数）。

## 5. 注意

- **Google は期日を保証しない**。`robots.txt` と `sitemap.xml` が正しくても、インデックスまでは**数日〜数週間**かかりうる。デモの直前ではなく、余裕をもって登録する。
- インデックスされると、**コンテスト結果ページも検索から到達できる**。順序を飛ばして結果に触れられる経路になるが、仕様として受け入れる（#77 リスク）。

## 6. 既知の制約（手順8の本名）

受賞者名は、段階7（`s07-contest-entry`）・段階8（`s08-real-name`）のフラグに応じて**クライアント側だけで描画**しており、サーバーHTML には含めていません（#239・#76「段階7の後だけ表示」）。そのため、Google の検索結果やスニペットから本名を読むことはできません。

手順8を Google 検索だけで成立させるには、名前をサーバーHTML に含める仕様変更が必要です。これは #76/#222 の「段階7の後だけ表示」と衝突するため、**実装では決めず、人の判断を待ちます**。
